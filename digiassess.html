Work / Design system for an assessment platform

A student reads question 27 under a timer. Every token in this system is built for that moment.

Digi 2.0 is the design system behind DigiAssess, an exam platform for students, proctors and exam co-ordinators. I built it in Figma from an audit of 300 product frames: five variable collections, 90 components and two themes. Every text and icon pair passes WCAG 2.2 AA in light and dark.

Starting point

300 frames of a working product. No single source for a colour, a size or a state.

I audited the Digi page of the UX file, 300 top-level frames covering scheduling, the co-ordinator dashboard, proctor monitoring, outcome analysis and the student exam. The product worked. The file had no shared rules behind it, and four gaps came up on screen after screen.

A brand blue too light for text

The main blue, #3E95EF, measures 3.1:1 on white. It filled buttons and coloured links, and AA asks for 4.5:1.

States told apart by colour

Attended and bookmarked question pills differed only in fill. A student with low colour vision could not tell where they had flagged a question.

Faint control borders

Text fields, selects and chips used a pale grey outline. On white, the edge of the field was hard to find.

No way to see focus

Most interactive components had no focused state, so a keyboard user lost their place on the exam screen.

Rules I set for the system

Five rules every variable and component had to pass.

Named for the jobaction/primary/bg, not blue/600. Primitives have no scopes, so they never show up in a fill picker.
AA in both themes4.5:1 for text. 3:1 for borders, icons and chart marks. Checked in Light and Dark.
Never colour aloneEvery state has a mark, a word or an outline as well as a fill.
Modes, not variantsTheme, density and screen size switch on the frame. No component has a "dark" or "mobile" variant.
Slots, not forksCard, Dialog, Drawer, Accordion item and Bottom sheet take any content through one instance swap.

Foundation one: variables

Raw values sit at the bottom and stay hidden. Screens only see names that say what a colour is for.

Primitives hold the ramps and are hidden from publishing. The Theme collection aliases them into roles and carries the Light and Dark modes. Every variable has explicit scopes and a WEB code syntax, so a developer inspecting a button reads var(--digi-action-primary-bg), not a hex value.

Foundation two: type

Roboto for everything you read. Roboto Mono for everything that counts down.

The product already ran on Roboto, so I kept it. The change was structure: 25 text styles, each bound to Typography variables for family, weight, size, line height and letter spacing. The question stem gets its own style with a 30px line height, because a student reads it more than once under a timer. Timers use Roboto Mono so the digits do not shift as they change.

Why one family

The exam app and the web product already used Roboto. Swapping the typeface would have touched every screen for little gain. The real wins came from the reading styles: an 18px stem on a 30px line, options at 16/24, and an overline for "Choose one" so the instruction is set apart from the answers without colour.

Foundation three: space, shape and depth

Space on a 4px grid with a 2px half step. Density is a mode, so a proctor table and an exam screen share one component.

The Scale collection holds 14 space steps, 8 radii, border widths, icon and avatar sizes, breakpoints and layout widths. Density lives in its own collection with Comfortable and Compact modes, so a co-ordinator table can drop to 40px rows while the student exam stays at full size.

Accessibility

I audited the finished library against WCAG 2.2 AA, fixed what failed, then measured again.

The check rendered every non-disabled variant in both themes and measured each piece of text and each icon against the fill behind it. Fixes went into the variables first, so one change reached every component that used them.

1,758Text checks across all non-disabled variants, both themes
366Icon checks against the fill behind them
0Failures after the fixes
25 of 25Interactive sets with a focused state
A darker blue for actionsblue/600 is #1A73D9 and fills primary buttons. Text and links use blue/700. The original #3E95EF stays as blue/500 for the selected answer border.
Borders you can findA new border/control variable gives Field, Select, Search, Chip, outlined Icon button and Stepper an edge of 3:1 or better.
Focus everywhereFocused variants added to 19 sets, each a 2px ring bound to border/focus. Button got an offset ring so it reads on blue.
Marks, not just fillsAttended and bookmarked pills carry an icon. Calendar today has an outline. Donut segments have gaps.
Room to growBadge, Timer, App header, Exam toolbar and six more use min-height instead of a fixed height, so they grow with their text.
Notes for developers40 components carry an "Accessibility:" line in their description with role, keyboard behaviour and naming.

Still to verify in code. Keyboard order and focus trapping, screen reader output, live region announcements and reflow at 200% zoom. Figma can measure colour. It cannot test these.

What I'd do differently

Get it into code sooner. Figma can prove the colours pass, but only a browser can test the rest.

Test with a keyboard and a screen reader

Focus order, focus trapping in dialogs, live region announcements and reflow at 200% are still unverified. I would build the exam screen in code next to the library, not after it.

Fix touch targets, not just note them

Checkbox, radio, chip remove, pager dot and the Compact density sit under 44px. I wrote that into their descriptions but did not resize them. 44px is AAA in WCAG 2.2, and on a phone during an exam it should be the floor.

Publish on day one

The library is not yet published as a team library and has no Code Connect. Publishing early would have put real teams on it while the names could still change cheaply.

Finish the data layer

The line chart from the outcome analysis screen is still a drawing, not a component. The data colours are ready for it. The chart itself is the next piece.
